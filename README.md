# Металлобаза55 — лендинг и прайс приёма лома (Омск)

Публично компания зовётся «Металлобаза55», отсюда и домен. Юридическое
наименование ООО «Вторресурс» осталось в реквизитах, документах и договорах.
Бренд лежит в `site.brand`, юрлицо — в `site.legalName`; в шаблонах не должно
быть ни того, ни другого текстом.

Серверное приложение на Node.js + Express + EJS. Обе страницы рендерятся на сервере
(важно для SEO), прайс хранится в JSON и правится через слой `src/lib/store.js` —
это задел под админку управления ценами.

**Продакшен:** [https://mbaza55.ru](https://mbaza55.ru) — работает по HTTPS,
сертификат Let's Encrypt с автопродлением.
Развёртывание, доступы и эксплуатация — в [docs/DEPLOY.md](docs/DEPLOY.md).
Выкатка обновлений: `ssh mbaza55 mbaza55-deploy`.

## Запуск

```bash
npm install
npm start
```

Дев-режим с автоперезапуском:

```bash
npm run dev
```

Приложение поднимается на `http://localhost:3000`. Переменные окружения:

| Переменная  | Назначение                                          | По умолчанию            |
|-------------|-----------------------------------------------------|-------------------------|
| `PORT`      | порт                                                 | `3000`                  |
| `HOST`      | интерфейс                                            | `0.0.0.0`               |
| `SITE_URL`  | боевой адрес — идёт в canonical, OG, sitemap, JSON-LD | `https://mbaza55.ru`      |
| `NODE_ENV`  | `production` включает кэш статики на 30 дней          | —                       |

## Структура лендинга

В сентябре 2026 года заказчик попросил убрать с главной всё, что читают
редко: порядок работы, блок про засор, FAQ и текстовый блок для организаций.
Ориентир — 74vtormet.ru, где нет ни одного абзаца. Порядок блоков сейчас:
первый экран → калькулятор суммы → пять плиток «что принимаем» → площадка
с картой → документы → контакты с формой. Отступ между блоками один на всю
страницу (`.section`), отдельного «плотного» варианта больше нет.

Убранный текст не потерян: второй владелец попросил не терять поисковые
формулировки, и весь информационный блок переехал на страницу
[`/kak-sdat`](#структура) — порядок приёмки, засор, документы и FAQ
с разметкой `FAQPage`. Главная отвечает на коммерческий запрос,
`/kak-sdat` — на информационный. Подробнее в [docs/SEO.md](docs/SEO.md).

Первый экран собран в одну колонку: адрес, заголовок, оффер, бегущая строка
цен, кнопки «Прайс-лист» и «Калькулятор», телефоны. Формы на нём нет и ленты
фактов тоже. Форма заявки на главной осталась одна, в блоке контактов
(`#zayavka-form`): туда ведут кнопка в шапке, кнопка из калькулятора
и редирект после отправки.

Тексты сведены к одной строке на блок. Подробные объяснения (засор, разделка,
условия приёма) живут на странице `/price`. Рейтинг 2ГИС стоит строкой
в панели под картой, отдельной секции у него нет. Документы и благодарности
собраны в один блок: слева реквизиты лицензий, справа сканы писем.

На всех пяти плитках «что принимаем» стоит верхняя цена. У плиток основного
прайса это максимум по категории, у радиолома и драгметаллов — максимум
по весовым позициям каталога (`catalogs.topPrice`): цену за штуку и за контакт
в этот расчёт не берём, рядом с ценой за килограмм она читалась бы как вес.

Прежние формулировки и разметка удалённых блоков есть в истории git.

Калькулятор и бегущая строка берут цифры из `data/prices.json` — второго
источника цен в проекте нет. Без JavaScript калькулятор показывает ссылку на
прайс, всё остальное работает как обычная страница.

Поле «что сдаёте» — не список из десятка позиций, а поиск по всему прайсу:
в разметке лежит пустой `<ul role="listbox">`, подсказки строит `main.js`
из того же JSON с ценами. В подсказки уходят только позиции с числовой ценой
(139 из 141): договорные посчитать нельзя. Пока поле пустое, сверху стоят
ходовые позиции из `content.popular`, дальше остальной прайс.

## Страницы цен

Три страницы устроены одинаково: `/price`, `/radiodetali` и `/dragmetally`.
Слева нумерованный список позиций с поиском наверху, справа липкий список
разделов. В шапке только H1: человек приходит за ценами и должен увидеть
таблицы сразу, поэтому крошки, вступительный абзац, бейджи и кнопку оттуда
убрали, а дату обновления перенесли в строку поиска.

Вид взят с прайса конкурента (74vtormet.ru/price), с которым заказчик
сверяет цены.

### Из чего собираются разделы

Групп на страницах не видно, в данных они остались: там их правят в админке
и оттуда берётся `OfferCatalog`.

| Страница | Разделы | Порядок |
|---|---|---|
| `/price` | категории прайса | `content.priceOrder` |
| `/radiodetali` | категории каталога | как в данных |
| `/dragmetally` | группы каталога | как в данных |

Уровень резки для каталогов задан полем `flatten` в `catalogs.REGISTRY`:
осмысленные названия лежат на разных уровнях. У радиодеталей это категории
(«Конденсаторы», «Реле»), у драгметаллов — группы («Серебро», «Золото»),
потому что категории там это подразделы вроде «Контакты», которые сами
по себе ничего не говорят и повторяются под разными металлами.

`content.priceOrder` повторяет порядок конкурента с одним отличием,
и оно от заказчика: у конкурента вольфрам стоит первым, а в Омске он
не развит, поэтому вольфрам и твёрдые сплавы ушли вниз, а список начинается
с чёрного лома, меди, латуни и алюминия. Категории, которых в списке нет,
показываются в конце — новую из админки не потеряем.

### Таблицы

Нумерация сквозная и считается счётчиком CSS: строки, скрытые поиском,
выпадают из счёта сами. Раздел длиннее `format.LONG_TABLE` строк (сейчас 40)
режется `format.chunk()` на две таблицы рядом, у каждой своя шапка. Это
случай разъёмов в радиодеталях: полторы сотни позиций, в столбик это семь
экранов подряд. Три колонки не влезают: у таблицы своя минимальная ширина
по содержимому, и на трети от 868 px она вылезала за край.

Описание позиции лежит в `<details>` и раскрывается по клику на название.
Не скрипт: так оно работает без JS, открывается с клавиатуры и остаётся
в разметке для поиска. Описания групп и вступительные абзацы страниц
не удалены, а перенесены в текстовый блок внизу — в них ГОСТ, перечисления
металлов и прочая семантика.

### Поиск

Прячет строки и опустевшие разделы вместе со ссылками на них, но весь прайс
остаётся в разметке: страница работает без JS, и поисковики видят все
позиции. Запрос ищется по всем словам в любом порядке, регистр и «ё»
не мешают; латинские и русские близнецы букв схлопываются, поэтому «3А»
кириллицей находит «3A» латиницей — в прайсе марки набраны вперемешку.
Нормализация общая с поиском в калькуляторе на главной (`normalize`
в `main.js`).

Подсветка раздела при прокрутке ограничена по времени, а не через
`requestAnimationFrame`: rAF не идёт, пока вкладка не отрисовывается,
и подсветка залипала на первом разделе.

## Шрифты

Oswald на заголовки и цифры, Golos Text на текст. Файлы лежат локально в
`public/fonts` (416 КБ на все начертания), подключаются через `@font-face`
в начале `public/css/style.css` с раздельными подмножествами для кириллицы и
латиницы и `font-display: swap`. Внешних запросов к Google Fonts нет.

Пересобрать блок `@font-face` при смене шрифтов можно из
`public/fonts/_manifest.json` — там записаны имена файлов, начертания и
unicode-range.

## Фотографии

`public/img/photo` — три ширины (640 / 1280 / 1920) в webp и jpg, отдаются через
`<picture>` из `views/partials/photo.ejs`.

⚠️ **Сейчас там временные снимки с Wikimedia Commons** по лицензиям CC BY,
CC BY-SA и CC0. Атрибуция обязательна и выводится в подвале блоком
«Фотографии на сайте — временные». Источник данных — `_credits.json`; если файла
нет, блок в подвале не рендерится.

Ни один снимок не подписан как площадка компании: стоковыми кадрами о самой
компании ничего не утверждается. Галерея площадки и фото весов в вёрстке
намеренно отсутствуют — их нельзя собрать из стока, не вводя клиента в
заблуждение. Список кадров для съёмки — в [docs/REBUILD.md](docs/REBUILD.md).

Скачивание и пережатие — `scripts/fetch-photos.js`. Список кадров, подписи
и кадрирование лежат в самом скрипте, `sharp` берётся из devDependencies:

```bash
node scripts/fetch-photos.js              # только недостающие слаги
node scripts/fetch-photos.js dragmet --force   # пересобрать один
```

Скрипт сам дописывает автора и лицензию в `_credits.json`. Руками этот файл
править не нужно: без строки в нём подпись в подвале не появится, а без
подписи лицензии CC BY и CC BY-SA нарушены.

## Прайс

`data/prices.json` — три группы (`chermet`, `cvetmet`, `redkozem`), 141 позиция.
Число позиций нигде не записано константой: главная и `description` страницы
цен считают его из данных (`countPositions()` в `src/routes/pages.js`), иначе
после первой же правки в админке цифра в тексте расходится с таблицей.
Структура позиции:

```json
{
  "id": "lom-medi-blesk",
  "title": "Лом меди «Блеск»",
  "note": "механически разделанный кабель, не окисленный…",
  "cash": 818.18,
  "cashTo": null,
  "bank": 900,
  "text": null
}
```

- `cash` — наличный расчёт (для чёрного лома — цена за тонну);
- `cashTo` — верхняя граница диапазона (`20 000 – 30 000`);
- `bank` — безналичный расчёт, показывается только для цветного лома;
- `text` — текстовая цена вместо числовой («до 40 000»), имеет приоритет.

Данные импортированы с [f-vm.ru/price](https://f-vm.ru/price/) и
[f-vm.ru/price_chermet](https://f-vm.ru/price_chermet/). Пересобрать из исходников:

```bash
node scripts/parse-source.js && node scripts/build-prices.js
```

⚠️ Пересборка перезаписывает `data/prices.json` целиком — после запуска админки
скрипты нужны только для разовых массовых импортов.

## Админка прайс-листа

Адрес: `/admin`. Открывается только когда в окружении задан `ADMIN_PASSWORD`;
без него роутер не подключается и `/admin` отдаёт обычную 404.

Что умеет:

- три каталога переключаются вкладками: основной прайс, радиодетали и платы,
  драгметаллы;
- в основном прайсе: цена, верхняя граница диапазона и текстовая цена
  вместо числа;
- в каталогах: единица измерения у каждой позиции и текстовая цена,
  у плат ещё и цена от 100 кг;
- правку названия и уточнения прямо в строке;
- добавление позиции в любую категорию, идентификатор строится из названия
  транслитерацией и при совпадении дополняется числом;
- удаление позиции через отдельную страницу подтверждения. Кнопка с `confirm()`
  не годится: без JavaScript она удаляла бы сразу и молча;
- сохранение только изменённых полей, дата обновления прайса ставится сама;
- список заявок с форм (уведомления пока не настроены, это единственный способ
  их увидеть).

Как заполняются цены — этим объяснением можно отвечать заказчику:

| Колонка | Что писать | Что увидит посетитель |
|---------|-----------|-----------------------|
| Цена | число: `818,18` или `1 200`, запятая и пробелы допустимы | `818,18 ₽/кг` |
| До | второе число, если цена зависит от состояния лома | `595–620 ₽/кг` вместо одного числа |
| Текстом | любая фраза: `до 40 000`, `договорная` | перебивает оба числа выше |

Пустая «Цена» без текста означает «цена по запросу». Пустая «До» — обычный
случай: цена показывается одним числом. В каталогах радиодеталей и
драгметаллов колонок «До» и «Текстом» нет: там цена сразу текстовая, потому
что в источнике встречаются `38 / 55` и `до 40 000`, а единица измерения
задаётся у каждой позиции отдельно.

Категории и группы через админку не редактируются намеренно: их идентификаторы
это якоря в прайсе, на которые ссылаются плитки главной, подвал и внешние
ссылки. Переименование категории тихо ломало бы их. Такие правки делаются
в `data/prices.json` вместе с обновлением ссылок.

Как устроена авторизация — `src/lib/auth.js`. Сессия это подписанная кука
`HttpOnly` + `SameSite=Strict`, сервер ничего не хранит. Внешних зависимостей
нет: `express-session` и `cookie-parser` ради одного администратора избыточны,
HMAC из `crypto` делает то же самое. Пароль сверяется `timingSafeEqual`, вход
ограничен восемью попытками за пятнадцать минут с адреса, у форм CSRF-токен,
привязанный к сессии. Страницы отдаются с `X-Robots-Tag: noindex` и
`Cache-Control: no-store`.

Сменить пароль на сервере:

```bash
ssh mbaza55 "sed -i 's/^ADMIN_PASSWORD=.*/ADMIN_PASSWORD=новый/' /srv/mbaza55/.env && systemctl restart mbaza55"
```

Смена `ADMIN_SECRET` разлогинивает открытые сессии, смена пароля — нет.

## SEO

Семантическое ядро, распределение запросов по блокам и чек-лист —
в [docs/SEO.md](docs/SEO.md).


- серверный рендеринг, уникальные `title`/`description`, `canonical`, OG/Twitter;
- по одному `<h1>` на страницу, семантическая иерархия заголовков;
- JSON-LD: `LocalBusiness`+`RecyclingCenter`, `WebSite`, `WebPage`,
  `BreadcrumbList`, `OfferCatalog` со 139 офферами, `FAQPage` на `/kak-sdat`
  (размечаем только те вопросы, которые видны на странице);
- `/robots.txt` и `/sitemap.xml` генерируются на лету, `lastmod` берётся из даты прайса;
- прайс — обычные HTML-таблицы, поиск фильтрует уже отрендеренный DOM,
  поэтому весь контент виден поисковикам без JS;
- страницы работают без JavaScript: форма уходит обычным POST с редиректом.

Знак — металлическая жар-птица из лома. Обложку и обе иконки собирает
`scripts/build-brand.js`:

```bash
node scripts/build-brand.js          # всё
node scripts/build-brand.js og       # только обложку
node scripts/build-brand.js icons    # только иконки
```

`logo.png` скрипт не трогает: он обрезан под высоту строки в шапке.

Текст на обложке набран тем же Oswald, что и заголовки сайта. librsvg берёт
шрифты через fontconfig и woff2 из `public/fonts` не читает, поэтому ttf-версии
лежат в `scripts/fonts` (там же README и лицензии OFL). Переменную
`FONTCONFIG_PATH` fontconfig читает при старте процесса, так что скрипт
готовит конфиг и перезапускает сам себя — иначе Oswald молча подменяется
системным моноширинным. На такую подмену есть проверка: если оба шрифта

У фавиконок фон намеренно непрозрачный тёмно-синий: птица на прозрачном фоне
была бы не видна во вкладке светлой темы. На 32 px знак дополнительно
осветляется почти до белого силуэта — серебристо-медные оттенки на таком
размере сливаются в пятно.

OG-обложка — именно PNG: большинство соцсетей не отображают SVG в `og:image`.
Её адрес, как и адреса иконок, идёт через `asset()` с хешем файла: соцсети
и мессенджеры кешируют превью по адресу картинки, и без смены адреса они
месяцами показывали бы обложку со старым названием компании.

Векторная иллюстрация грейфера из старого первого экрана удалена — её место
заняла фотография.
