# Вторресурс — лендинг и прайс приёма лома (Омск)

Серверное приложение на Node.js + Express + EJS. Обе страницы рендерятся на сервере
(важно для SEO), прайс хранится в JSON и правится через слой `src/lib/store.js` —
это задел под админку управления ценами.

**Продакшен:** [https://mbaza55.ru](https://mbaza55.ru) — работает по HTTPS,
сертификат Let's Encrypt с автопродлением.
Развёртывание, доступы и эксплуатация — в [docs/DEPLOY.md](docs/DEPLOY.md).
Выкатка обновлений: `ssh mbaza55 mbaza55-deploy`.

## Запуск

```bash
npm install
npm start
```

Дев-режим с автоперезапуском:

```bash
npm run dev
```

Приложение поднимается на `http://localhost:3000`. Переменные окружения:

| Переменная  | Назначение                                          | По умолчанию            |
|-------------|-----------------------------------------------------|-------------------------|
| `PORT`      | порт                                                 | `3000`                  |
| `HOST`      | интерфейс                                            | `0.0.0.0`               |
| `SITE_URL`  | боевой адрес — идёт в canonical, OG, sitemap, JSON-LD | `https://mbaza55.ru`      |
| `NODE_ENV`  | `production` включает кэш статики на 30 дней          | —                       |

## Структура

```
server.js                — точка входа
src/app.js               — express-приложение, middleware, обработка 404/500
src/config/site.js       — контакты, реквизиты, адрес, координаты, режим, SEO-умолчания
src/content/index.js     — тексты лендинга: оффер, плитки, шаги, засор, FAQ, витрины
src/content/privacy.js   — текст политики обработки персональных данных
src/lib/store.js         — доступ к основному прайсу и заявкам (чтение + запись)
src/lib/catalogs.js      — радиодетали и драгметаллы (только чтение)
src/lib/format.js        — форматирование цен и дат
src/lib/seo.js           — сборка JSON-LD (LocalBusiness, FAQPage, OfferCatalog, крошки)
src/routes/pages.js      — роуты: /, /price, /privacy, /lead, robots.txt, sitemap.xml
views/                   — EJS-шаблоны
views/partials/photo.ejs — адаптивная картинка (webp + jpg, три ширины)
views/catalog.ejs        — общий шаблон страниц радиодеталей и драгметаллов
public/css/style.css     — единая таблица стилей, включая @font-face
public/fonts/            — Oswald и Golos Text, кириллица и латиница раздельно
public/img/photo/        — фотографии блоков + _credits.json с атрибуцией
data/prices.json         — основной прайс: чёрный, цветной, редкоземельный лом
data/radio.json          — радиодетали и платы (страница /radiodetali)
data/dragmet.json        — драгметаллы (страница /dragmetally)
data/leads.json          — заявки с форм
scripts/                 — разовые скрипты импорта прайса
```

## Структура лендинга

Порядок блоков на главной и задача каждого — в [docs/REBUILD.md](docs/REBUILD.md).
Коротко: первый экран с фотографией и формой → бегущая строка цен → полоса
доверия → калькулятор суммы → три плитки «что принимаем» → шаги приёмки →
блок про засор → площадка с картой → рейтинг 2ГИС → блок для организаций →
FAQ → финальный призыв.

Калькулятор и бегущая строка берут цифры из `data/prices.json` — второго
источника цен в проекте нет. Без JavaScript калькулятор показывает ссылку на
прайс, всё остальное работает как обычная страница.

## Шрифты

Oswald на заголовки и цифры, Golos Text на текст. Файлы лежат локально в
`public/fonts` (416 КБ на все начертания), подключаются через `@font-face`
в начале `public/css/style.css` с раздельными подмножествами для кириллицы и
латиницы и `font-display: swap`. Внешних запросов к Google Fonts нет.

Пересобрать блок `@font-face` при смене шрифтов можно из
`public/fonts/_manifest.json` — там записаны имена файлов, начертания и
unicode-range.

## Фотографии

`public/img/photo` — три ширины (640 / 1280 / 1920) в webp и jpg, отдаются через
`<picture>` из `views/partials/photo.ejs`.

⚠️ **Сейчас там временные снимки с Wikimedia Commons** по лицензиям CC BY,
CC BY-SA и CC0. Атрибуция обязательна и выводится в подвале блоком
«Фотографии на сайте — временные». Источник данных — `_credits.json`; если файла
нет, блок в подвале не рендерится.

Ни один снимок не подписан как площадка компании: стоковыми кадрами о самой
компании ничего не утверждается. Галерея площадки и фото весов в вёрстке
намеренно отсутствуют — их нельзя собрать из стока, не вводя клиента в
заблуждение. Список кадров для съёмки — в [docs/REBUILD.md](docs/REBUILD.md).

Пережать новые фотографии (нужен `sharp` из devDependencies):

```bash
node -e "require('sharp')" # проверка, что зависимость на месте
```

## Прайс

`data/prices.json` — две группы (`chermet`, `cvetmet`), 22 категории, 141 позиция.
Структура позиции:

```json
{
  "id": "lom-medi-blesk",
  "title": "Лом меди «Блеск»",
  "note": "механически разделанный кабель, не окисленный…",
  "cash": 818.18,
  "cashTo": null,
  "bank": 900,
  "text": null
}
```

- `cash` — наличный расчёт (для чёрного лома — цена за тонну);
- `cashTo` — верхняя граница диапазона (`20 000 – 30 000`);
- `bank` — безналичный расчёт, показывается только для цветного лома;
- `text` — текстовая цена вместо числовой («до 40 000»), имеет приоритет.

Данные импортированы с [f-vm.ru/price](https://f-vm.ru/price/) и
[f-vm.ru/price_chermet](https://f-vm.ru/price_chermet/). Пересобрать из исходников:

```bash
node scripts/parse-source.js && node scripts/build-prices.js
```

⚠️ Пересборка перезаписывает `data/prices.json` целиком — после запуска админки
скрипты нужны только для разовых массовых импортов.

## Админка прайс-листа

Адрес: `/admin`. Открывается только когда в окружении задан `ADMIN_PASSWORD`;
без него роутер не подключается и `/admin` отдаёт обычную 404.

Что умеет:

- редактирование цен по группам: наличные, верхняя граница диапазона, безнал
  и текстовая цена вместо числа;
- правку названия и уточнения прямо в строке;
- добавление позиции в любую категорию, идентификатор строится из названия
  транслитерацией и при совпадении дополняется числом;
- удаление позиции через отдельную страницу подтверждения. Кнопка с `confirm()`
  не годится: без JavaScript она удаляла бы сразу и молча;
- сохранение только изменённых полей, дата обновления прайса ставится сама;
- список заявок с форм (уведомления пока не настроены, это единственный способ
  их увидеть).

Категории и группы через админку не редактируются намеренно: их идентификаторы
это якоря в прайсе, на которые ссылаются плитки главной, подвал и внешние
ссылки. Переименование категории тихо ломало бы их. Такие правки делаются
в `data/prices.json` вместе с обновлением ссылок.

Как устроена авторизация — `src/lib/auth.js`. Сессия это подписанная кука
`HttpOnly` + `SameSite=Strict`, сервер ничего не хранит. Внешних зависимостей
нет: `express-session` и `cookie-parser` ради одного администратора избыточны,
HMAC из `crypto` делает то же самое. Пароль сверяется `timingSafeEqual`, вход
ограничен восемью попытками за пятнадцать минут с адреса, у форм CSRF-токен,
привязанный к сессии. Страницы отдаются с `X-Robots-Tag: noindex` и
`Cache-Control: no-store`.

Сменить пароль на сервере:

```bash
ssh mbaza55 "sed -i 's/^ADMIN_PASSWORD=.*/ADMIN_PASSWORD=новый/' /srv/mbaza55/.env && systemctl restart mbaza55"
```

Смена `ADMIN_SECRET` разлогинивает открытые сессии, смена пароля — нет.

## SEO

Семантическое ядро, распределение запросов по блокам и чек-лист —
в [docs/SEO.md](docs/SEO.md).


- серверный рендеринг, уникальные `title`/`description`, `canonical`, OG/Twitter;
- по одному `<h1>` на страницу, семантическая иерархия заголовков;
- JSON-LD: `LocalBusiness`+`RecyclingCenter`, `WebSite`, `WebPage`, `FAQPage`,
  `BreadcrumbList`, `OfferCatalog` со 139 офферами;
- `/robots.txt` и `/sitemap.xml` генерируются на лету, `lastmod` берётся из даты прайса;
- прайс — обычные HTML-таблицы, поиск фильтрует уже отрендеренный DOM,
  поэтому весь контент виден поисковикам без JS;
- страницы работают без JavaScript: форма уходит обычным POST с редиректом.

Знак — жар-птица в белом с золото-оранжевым оперением. Птица вырезана с
однородного тёмного фона с восстановлением цвета (unpremultiply), поэтому по
краям нет тёмной каймы. У фавиконок фон намеренно непрозрачный тёмно-синий:
белая птица на прозрачном фоне была бы не видна во вкладке светлой темы.

OG-обложка — именно PNG: большинство соцсетей не отображают SVG в `og:image`.

Векторная иллюстрация грейфера из старого первого экрана удалена — её место
заняла фотография.
